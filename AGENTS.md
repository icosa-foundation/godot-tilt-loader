# Project Memory

- The GDScript brush runtime is intended to be a direct conversion of the working C# brush runtime, not a behavioral rewrite.
- The project still has two C# references:
  - upstream Open Brush C# source,
  - the Godot .NET C# port on another branch.
- For mesh parity work, prefer the Godot .NET C# port as the immediate oracle for C#-to-GDScript conversion parity, and use upstream Open Brush C# as the source-of-truth reference when investigating C# behavior.
- Do not reinvent mesh behavior with hand-derived expectations when a same-input C# vs GDScript mesh comparison can be used instead.

# Repository Guidelines

## Project Structure & Module Organization

- This is a Godot 4 GDScript project rooted at the repository root; open this directory directly in Godot.
- Runtime scripts live under `Scripts/`; brush implementations are under `Scripts/Brushes`, and shared helpers are under `Scripts/Util`.
- Scenes live under `Scenes/`, tests under `Tests/GDScript/`, and brush resources under `Resources/` plus the root manifest assets.
- Godot addons live under `addons/`. The Icosa addon at `addons/icosa/` is generated by gd-plug and ignored by git.
- `plug.gd` is the addon dependency manifest. `addons/gd-plug/plug.gd` is the gd-plug bootstrap script.

## Build, Test, and Development Commands

- Install addon dependencies from the repository root:
  `godot --headless --xr-mode off --path . --script res://plug.gd install`
- Run a GDScript test from the repository root:
  `godot --headless --xr-mode off --path . --script res://Tests/GDScript/<TestName>.gd`
- Open the repository root in normal non-.NET Godot for editor work.

## Coding Style & Naming Conventions

- Use GDScript with tab indentation, matching the existing files.
- Preserve the ported Open Brush field names where parity with the original runtime matters, such as `m_ControlPoints` and `m_BrushGuid`.
- Prefer local helper APIs and existing brush/runtime patterns over new abstractions.

## Testing Guidelines

- Add focused GDScript tests under `Tests/GDScript/`.
- Use controlled Godot console runs with stdout/stderr captured and a hard timeout when validating through automation.
- Do not ask the user to check the Godot console; write or capture logs where this agent can read them.

## Commit & Pull Request Guidelines

- Keep commits focused and imperative.
- Do not commit generated addon payloads such as `addons/icosa/` or gd-plug cache content under `.plugged/`.
- Do not reintroduce Unity `Assets/`, `Packages/`, or `ProjectSettings/` project structure.
